# CLAUDE.md — Awesome Claude Code

This file provides codebase orientation for AI assistants working in this repository.

## What This Repository Is

**awesome-claude-code** is a curated "awesome list" of resources for Claude Code — slash-commands, CLAUDE.md files, hooks, agent skills, status lines, tooling, and official documentation. It is implemented as a **multi-list**: a single CSV source of truth generates multiple README views (visual, classic, awesome-list style, and 44 flat/tabular variants).

The repo is effectively a full-stack application hosted entirely on GitHub, with automation for resource submissions, validation, PR creation, and README generation.

## Development Commands

All commands use the Makefile. **In CI, `python3` is used; locally, `venv/bin/python3`.**

```bash
make install               # Create venv and install all dependencies (run this first)

# Day-to-day development
make test                  # Run pytest
make ci                    # Full CI: format-check + mypy + test + docs-tree-check
make format                # Auto-fix code style with ruff
make format-check          # Check style without fixing (used in CI)
make mypy                  # Type checking

# README pipeline
make generate              # Regenerate all READMEs from CSV (runs sort first)
make sort                  # Sort THE_RESOURCES_TABLE.csv by category/subcategory/name
make test-regenerate       # Verify generate produces a clean git tree (CI integrity check)
make test-regenerate-cycle # Full cycle test: exercises root_style and style_order changes

# Resource management
make validate              # Validate all resource URLs
make validate-single URL=<url>    # Validate a single URL
make add-category          # Interactive: add a new category
make generate-resource-id  # Interactive: generate a resource ID
make download-resources    # Download resources from GitHub into resources/

# Maintenance
make docs-tree             # Update the file tree in README-GENERATION.md
make docs-tree-check       # Verify the tree is up to date (used in CI)

make clean                 # Remove caches and test artifacts
make clean-all             # Also remove venv/
```

## The README Generation Pipeline

**Never manually edit `README.md` or any file in `README_ALTERNATIVES/`.** These are fully generated artifacts. The pipeline is:

```
THE_RESOURCES_TABLE.csv
  + templates/categories.yaml
  + templates/*.template.md
  + templates/announcements.yaml
  → scripts/readme/generate_readme.py
      → README.md                        (root style, set in acc-config.yaml)
      → README_ALTERNATIVES/README_EXTRA.md
      → README_ALTERNATIVES/README_CLASSIC.md
      → README_ALTERNATIVES/README_AWESOME.md
      → README_ALTERNATIVES/README_FLAT_*.md  (44 files: 11 categories × 4 sorts)
      → assets/badge-*.svg               (navigation badges, regenerated in-place)
```

To regenerate after any data change: `make generate`

### README Styles

| Style | Generator Class | Description |
|-------|----------------|-------------|
| `extra` | `VisualReadmeGenerator` | SVG-heavy visual theme |
| `classic` | `MinimalReadmeGenerator` | Plain markdown, collapsible sections |
| `awesome` | `AwesomeReadmeGenerator` | Clean awesome-list format |
| `flat` | `ParameterizedFlatListGenerator` | 44 tabular views (category × sort) |

The `root_style` in `acc-config.yaml` determines which style is also written to `README.md`.

### Asset Path Resolution

Templates **never hardcode relative paths** to assets. Use placeholders:
```
{{ASSET_PATH("filename.svg")}}   or   asset:filename.svg
```
The generator resolves these to correct relative paths for each output file's location.

The generator anchors on the repo root by finding `pyproject.toml` (via `find_repo_root()`).

## Data Model

### THE_RESOURCES_TABLE.csv

The master resource table. All README generation reads from this file. Key fields include: `ID`, `Name`, `Category`, `Sub-Category`, `Primary Link`, `Description`, `License`, `Author`, `Created`, `Updated`.

### Resource IDs

Format: `{prefix}-{hash8}` where:
- `prefix` comes from the category (e.g., `skill`, `cmd`, `hook`, `claude`, `tool`, `wf`, `doc`, `status`)
- `hash8` = first 8 hex chars of SHA256(`display_name` + `primary_link`)

Generate interactively: `make generate-resource-id`

### categories.yaml

Single source of truth for categories and subcategories. Adding a category here automatically propagates to all scripts and templates. Structure:
```yaml
categories:
  - id: skills
    name: "Agent Skills"
    prefix: skill
    icon: "🤖"
    order: 1
    subcategories:
      - id: general
        name: "General"
```

## Submission & Automation

Resource submissions go through GitHub Issue forms → bot validation → maintainer approval → automated PR creation. The automation is entirely in `.github/workflows/`.

**Do not submit resources via PR.** The full submission flow is documented in `docs/CONTRIBUTING.md`.

Maintainer commands (posted as issue comments):
- `/approve` — triggers automated PR creation
- `/reject [reason]` — closes submission
- `/request-changes [reason]` — requests edits

## Code Style & Conventions

- **Python 3.11+**, enforced via `.python-version` and `pyproject.toml`
- **Ruff** for linting and formatting (line-length 100). Run `make format` to auto-fix.
- **mypy** for type checking. Run `make mypy`.
- **Pre-commit hooks**: ruff + tests + README-generation check (via `.pre-commit-config.yaml`)
- **CI gate**: `make ci` = format-check + mypy + test + docs-tree-check

### Module Imports

All scripts are run as modules from the repo root:
```bash
python -m scripts.readme.generate_readme        # correct
python scripts/readme/generate_readme.py        # wrong (path-based, breaks imports)
```

Scripts that are CLI entry points must include `if __name__ == "__main__":`.

In GitHub Actions, set `PYTHONPATH: ${{ github.workspace }}` so `scripts.*` imports resolve.

### Sparse Checkouts (GitHub Actions)

Any workflow using sparse checkout **must include `pyproject.toml`** so `find_repo_root()` can locate the repo root. Also include any data files the script reads (`THE_RESOURCES_TABLE.csv`, `templates/`, etc.).

## What NOT to Do

- **Do not manually edit** `README.md`, `README_ALTERNATIVES/*.md`, or `assets/badge-*.svg` — all are generated.
- **Do not run scripts with slash paths** (`python scripts/foo.py`) — use `python -m scripts.foo`.
- **Do not add resources by PR** — use the GitHub Issue form submission process.
- **Do not hardcode asset paths in templates** — use `{{ASSET_PATH("...")}}` placeholders.
- **Do not commit with `--no-verify`** unless explicitly requested — pre-commit hooks enforce format + test + README freshness.
